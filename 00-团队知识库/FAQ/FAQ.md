# FAQ（团队共享）

## 1. 如何和 Cursor AI 长期共建文档？

- 以 Git 仓库中的 Markdown 为单一事实源。
- 所有角色按模板维护文档（需求、研发、设计、测试、运维）。
- 每次重要变更通过 Git 提交，保留历史与可追溯性。
- 项目文档写在项目 `docs/`，跨项目知识沉淀到本知识库。

## 2. 为什么终端里 `cd` 失败？

- 目录路径包含空格，需要使用双引号或转义空格。
- 示例：
  - `cd "/Users/yangyong/Documents/快看漫画_工作/K 智能体/Vibe Coding/AI渠道数据分析工具"`

## 3. 为什么 `git add "AI渠道数据分析工具"` 会报未匹配文件？

- 当你已经在 `AI渠道数据分析工具` 目录内时，不应再 `add` 同名路径。
- 正确写法：
  - 当前目录提交：`git add .`
  - 上级目录提交：`git add "AI渠道数据分析工具"`

## 4. 渠道 AI 数据分析平台的 MVP 边界是什么？

- 不自动执行投放动作（预算、出价、停投都需人工确认）。
- 先覆盖核心渠道，优先做人审辅助决策和闭环沉淀。
- 关联项目需求：`AI渠道数据分析工具/docs/requirements/2026-04-28-渠道AI数据分析平台.md`

## 5. 需求文档该怎么写，才方便 AI 完善和评估研发可行性？

- 先写 6 个最小模块：背景与问题、量化目标、非目标、核心场景、验收标准、约束条件。
- 验收标准要可测试，避免抽象表述；建议使用勾选清单并给出阈值。
- 明确本期范围边界（MVP 覆盖渠道、时间窗、角色权限），避免研发排期失真。
- 写完后让 AI 按“清晰度、可行性、分期、工作量、风险”5 维评审并补全技术方案。

## 6. 如何让产品、研发、设计、测试、运维共同维护同一项目？

- 在项目 `docs/` 下按角色建模块并统一模板：`requirements/`、`engineering/`、`design/`、`testing/`、`operations/`、`decisions/`、`project/`。
- 每个需求至少配套 4 份文档：需求文档、技术方案、测试计划、决策记录。
- 用 `project/RACI.md` 明确谁负责、谁审批、谁协作、谁知会。
- 通过 Git 小步提交，确保所有角色的变更可追溯、可评审。

## 7. 如何把单项目知识库升级为全项目共享知识库？

- 在仓库根目录创建 `00-团队知识库/`，统一沉淀跨项目 FAQ、模板、规范和方法论。
- 项目内保留 `docs/knowledge/README.md` 作为入口，指向共享知识库，避免重复维护多份副本。
- 共享内容放 `00-团队知识库/`，项目私有内容继续放各项目 `docs/`。
- 建议每周一次把高频问答合并到 `FAQ/FAQ.md` 并更新 `INDEX.md`。

## 8. Git 操作有没有一份可直接照做的完整指引？

- 有，已整理为操作手册：`00-团队知识库/Playbooks/Git与GitHub协作操作手册.md`
- 包含内容：本地 Git 基础、GitHub 同步、提交更新、拉取项目、常见报错处理。

## 9. 怎么判断我是不是在 Git 仓库里？仓库根目录在哪里？

- 查看仓库根目录：
  - `git rev-parse --show-toplevel`
- 查看当前目录：
  - `pwd`
- 判断是否在仓库内：
  - `git status -sb`
  - 若报错 `not a git repository`，说明当前目录不在 Git 仓库中。
- 判断是否在同一个仓库：
  - 只要 `pwd` 是 `git rev-parse --show-toplevel` 返回路径的子路径，就在同一仓库内。
