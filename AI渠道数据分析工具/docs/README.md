# 文档中心

这里是团队协作的统一文档入口。所有内容都尽量结构化，方便人读和 AI 解析。

## 文档结构

- `requirements/`：需求文档与验收
- `engineering/`：研发方案、技术设计、接口与数据模型
- `design/`：交互与视觉方案、设计规范与评审记录
- `testing/`：测试计划、用例与上线验收
- `operations/`：上线、监控、告警、故障与复盘
- `playbook/`：投放经验与操作手册
- `decisions/`：关键决策记录
- `knowledge/`：项目知识入口（跳转到仓库级共享知识库）
- `project/`：协作机制（RACI、评审节奏、版本计划）

## 文档命名建议

- 需求：`YYYY-MM-DD-主题.md`
- 研发设计：`YYYY-MM-DD-技术方案-主题.md`
- 设计稿说明：`YYYY-MM-DD-设计方案-主题.md`
- 测试计划：`YYYY-MM-DD-测试计划-主题.md`
- 经验：`YYYY-MM-DD-渠道-问题.md`
- 决策：`ADR-XXX-主题.md`
- 问答沉淀：统一维护在仓库级 `00-团队知识库/`

## 维护约定

- 每篇文档要有 owner 和更新时间。
- 每个结论必须可追溯（数据、规则或案例）。
- 重要变更用 Git 提交信息说明原因，不只写改了什么。
- 每个需求至少要有：需求文档 + 技术方案 + 测试计划 + 决策记录。
- 跨项目通用问答与规范统一维护在 `00-团队知识库/`，项目内不重复存储。
